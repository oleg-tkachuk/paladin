# Logging

The `paladin` uses [`go.uber.org/zap`](https://pkg.go.dev/go.uber.org/zap) for structured, high-performance logging.

## 1. Initialization

Logging initialized during bootstrap within `internal/logger/logger.go`:

- **Global Logger:** `zap.ReplaceGlobals(log)` allows components to use `zap.L()`.
- **Contextual Logger:** A context-aware wrapper `logger.FromContext(ctx)` is heavily used. It automatically extracts OpenTelemetry `trace_id` and `span_id` from the context to correlate logs with distributed traces.

## 2. Log Event Taxonomy

- **Request Logs**: Automatically generated by HTTP and gRPC interceptors (`internal/middleware.RequestLogger`).
- **Dependency Logs**: E.g., S3 client failures, DB connection acquisition logs (if debug enabled).
- **Worker Logs**: Emitted by background jobs (e.g., `Reaper` logs regarding orphaned multipart uploads and soft-delete purges).

## 3. Standard Structured Fields

Logs are enriched at two levels:

**Global Fields (Attached at startup):**

- `service` (e.g., `"paladin"`)
- `env` (e.g., `"production"`)
- `k8s_namespace` (Extracted from environment variables)

**Contextual Fields (Per-request/Per-span):**

- `trace_id`
- `span_id`
- `request_id` (Generated or extracted from headers)
- `tenant_id` (Extracted from authentication context or headers)

**HTTP Request Log Fields:**

- `http.request.method`
- `url.path`
- `http.response.status_code`
- `duration` (latency)
- `client.address`

## 4. Redaction & Security Rules

- **PII & Secrets:** Passwords and tokens are strictly excluded from HTTP request logs.
- Sensitive payload bodies are never logged by the standard request logger.
- The `config.Security.LogSensitive` configuration toggles whether certain debugging data is permitted in lower environments.
- Kubernetes probes (`/health/livez`, `/health/readyz`) and metrics (`/metrics`) are explicitly suppressed or downgraded to `DEBUG` levels to prevent log spam (configurable via `server.log_probes`).
